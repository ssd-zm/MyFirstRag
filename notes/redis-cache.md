# Redis 缓存问题笔记

## 缓存穿透

穿透是指查询一个根本不存在的 key，请求直接打到数据库。两种常见兜底方式：一是用布隆过滤器提前挡掉一定不存在的 key；二是把空结果也缓存起来，给一个很短的过期时间，比如 60 秒。

布隆过滤器有误判率，说存在的 key可能实际不存在，但说不存在的 key一定不存在，所以只能用来挡，不能用来判断一定存在。

## 缓存击穿

击穿是指某个热点 key 刚好过期，大量并发请求同时涌向数据库。解决办法是加互斥锁，只让一个线程去回源，其他线程等待后读缓存；或者热点 key 干脆不设过期时间，靠后台任务更新。

## 缓存雪崩

雪崩是大量 key 在同一时间过期，或者 Redis 整个挂掉。给过期时间加随机偏移量是最简单的办法，比如基础时间上加 0 到 300 秒的随机值。生产环境还要考虑集群和降级。

## 一致性策略

常用的是先更新数据库再删除缓存，也就是 Cache Aside。删除失败时靠消息队列重试或者订阅 binlog 补偿。不要用先删缓存再写数据库，并发下容易把旧值写回缓存。
